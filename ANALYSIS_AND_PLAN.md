## 3. Разрыв с целью

Цель (из ТЗ): **децентрализованное обучение + гибридный ИИ-оракул + управление физическими процессами.**

В текущем репо из этого есть только **LLM-интеграция** (Ollama). Чего нет вообще:

- ❌ Федеративного обучения (Federated Learning) — устройства/шлюзы не обучают модели.
- ❌ ИИ-оракула (анализ данных, прогнозы, аномалии).
- ❌ Интеграции с Axis Core (`axis_core.policy`, оракул, реестр устройств).
- ❌ Рыночных данных (цены на энергию).
- ❌ Управления физическими процессами (автоторговля, оптимизация).
- ❌ Пакетной упаковки (pyproject/requirements), pytest-тестов, папки `projects/`.

**Вывод:** ENRG-AI сейчас — «инструмент для разработчика», а нужен «слой интеллекта экосистемы». Надстройка поверх существующего каркаса.

## 4. Архитектурный план (трёхслойная система)

```
┌────────────────────────────────────────────────────────────┐
│ 3. СЛОЙ ИНТЕЛЛЕКТА (ENRG-AI)                                │
│    SignalProvider (аномалии/прогнозы/рынок)                  │
│    Federated Learning (веса от шлюзов, FedAvg)               │
│    Market feed (цены)                                        │
│         │                                                    │
│         ▼ (сигналы, НЕ решения)                              │
│ 2. СЛОЙ ДОВЕРИЯ (Axis Core)                                  │
│    Verifier (криптография) → Policy Engine (решения)         │
│    Device Registry (история, ERS)                            │
│         │                                                    │
│         ▼ (верифицированные отчёты)                          │
│ 1. ФИЗИЧЕСКИЙ СЛОЙ (ENRG)                                    │
│    ESP32/gateway → Ed25519-подпись → Oracle (Node.js)        │
│    └── on-chain: enrg-mvp (mint_energy, EnergyProducer PDA)  │
└────────────────────────────────────────────────────────────┘
```

**Главный принцип (конституция):** ИИ-оракул — **источник сигналов, а не решений.** Он производит «наблюдения» (аномалия, прогноз, рыночная рекомендация), а решение о применении принимает **Policy Engine** (ADR-0003). Так ИИ не становится новым «центром», а остаётся ещё одним проверяемым слоем.

### 4.1. Как связать с Axis Core

Новый модуль в Axis Core — `axis_core/ai/`:

| Модуль | Назначение |
|---|---|
| `axis_core/ai/__init__.py` | публичный интерфейс |
| `axis_core/ai/signal_provider.py` | `SignalProvider` — единая точка запроса ИИ-сигналов |
| `axis_core/ai/anomaly.py` | поведенческий анализ отчётов устройства (история, ERS, неожиданные скачки) |
| `axis_core/ai/forecast.py` | прогноз выработки (объединяет локальные модели шлюзов + внешние данные) |
| `axis_core/ai/market.py` | рыночные фиды цен (нормализация, кэш) |

Интеграция по шагам:
1. **Oracle (ENRG `server.js` / `policy.js`)** — после криптографической верификации вызывает `SignalProvider` (опционально, если политика включена).
2. **Policy Engine (`axis_core.policy`)** — новые параметры политики:
   - `enforce_ai_anomaly: bool` — использовать ИИ-аномалию как сигнал;
   - `ai_anomaly_threshold: float` — порог срабатывания;
   - `ers_weight` — вес репутации устройства (уже есть ERS).
   Решение остаётся за политикой: аномалия от ИИ **не блокирует** автоматически, а **помечает** (влияет на ERS/quarantine через `report_anomaly`), если политика так настроена.
3. **Registry (EnergyProducer PDA / `registry_service`)** — ИИ-оракул читает историю устройства (month_energy, ERS, nonce) для контекста.

### 4.2. Федеративное обучение (Federated Learning)

```
Шлюзы/устройства (локальные данные)
   │  обучают лёгкую модель (linear/малая NN)
   ▼  подписывают обновление (Ed25519 — ключ устройства)
Агрегатор ENRG-AI (FedAvg: среднее весов/градиентов)
   │  верификация подписей + качества
   ▼
Глобальная модель → используется SignalProvider (прогноз/аномалия)
```

Ключевые решения:
- **Обучение — на шлюзе, не на ESP32.** ESP32 потянет только инференс лёгкой модели; обучение — на хосте шлюза (Raspberry Pi / ПК фермы). Это честно по вычислительным ограничениям.
- **Подпись вклада:** каждое обновление весов подписывается ключом устройства (Ed25519) — тот же паттерн, что и для proof-of-production (конституция: ключ не покидает устройство, вклад проверяем).
- **Агрегация:** FedAvg (усреднение) на первом этапе; позже — FedProx/FedSGD по мере роста.
- **Качество:** агрегатор отклоняет выбросы (низкий вклад, неподписанные обновления). Стимул за качество — не отдельный минт (SRC только за верифицированную энергию), а репутация + участие в DAO-решениях.

Новые модули в ENRG-AI: `agent/fed/` (`local_train.py`, `aggregate.py`, `protocol.py` — формат подписанного вклада).

### 4.3. Рыночные данные (цены на энергию)

- `agent/market/feeds.py` — нормализованные фиды цен (day-ahead биржи, P2P-ориентиры), кэш, периодическое обновление.
- `agent/market/model.py` — структура «цена × время» для прогноза.
- Использование: `SignalProvider` комбинирует **верифицированную выработку + прогноз + цену** → рекомендацию (продать/накопить/купить).
- Ограничение: рекомендация попадает в Policy Engine / DAO, **не** автономная торговля с одного оракула (риск централизации).

## 6. Риски и меры

| Риск | Мера |
|---|---|
| ИИ становится новым «центром доверия» | ИИ = сигналы, решения = Policy Engine (ADR-0003); сигналы проверяемы |
| Отравление федеративного обучения (bad weights) | Подписи вкладов + отсев выбросов + репутация шлюзов |
| ESP32 не тянет ML | Инференс лёгких моделей на ESP32, обучение на шлюзе |
| Рыночные данные = централизация | Несколько фидов, нормализация, решения через политику/DAO |
| Приватность данных устройств | Передаются веса/градиенты, а не сырые данные (FL) |
